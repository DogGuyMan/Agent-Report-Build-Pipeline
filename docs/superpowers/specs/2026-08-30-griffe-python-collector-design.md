# griffe 기반 Python 정적 수집기 — 설계 검토

`machine/normalize.py` 에 세 번째 언어 갈래 `normalize_python()` 을 더해, griffe 가 낸 Python
덤프를 기존 두 언어(C++ · C#)와 같은 `codegraph.json`(schema_version 2)으로 정규화한다.

실행 계획 전문은 `docs/superpowers/plans/2026-08-30-griffe-python-collector.md` 에 있다.
이 문서는 **수용 판정에 필요한 것만** 남긴 요약이다.

## 배경 — 인계 문서의 전제 두 개가 무너졌다

인계 문서 `docs/handoffs/HANDOFF-2026-08-29-griffe-python-prototype.md` 는 griffe 를 설치해
보지 못한 채 쓰였다. 2026-08-30 세션이 실제로 설치(griffe 2.2.0)해 돌려 본 결과 두 전제가
사실이 아니었다.

| 인계 문서의 주장 | 실측 |
|---|---|
| griffe 는 타입힌트를 **문자열**로 준다 → R5 구현 불가 | **구조화된 식 트리**로 준다. C# 의 `generic_def`+`type_args` 와 같은 모양 |
| `machine/` 자기호스팅으로 골든 테스트를 만들 수 있다 | 클래스 1개 · 상속 0개 · 타입주석 0개. 빈 그래프를 검증하게 된다 |
| `members` 가 v1 부터 list → dict 로 바뀐다 | 이미 dict 다 |

## Decision Log

### D0 · griffe 를 Python 정적 수집기로 채택한다 (Option B)

- Status: `[승인됨]` — 사용자 승인(2026-08-29), 범위는 Python 만. ts-morph/JS-TS 는 범위 밖
- 확신도: 🔵 92 — 실제로 설치해 `machine/` 을 덤프하고 출력 구조를 눈으로 확인했다
- 옵션 2 (기성 라이브러리 griffe / 자작 `ast` 덤퍼)

### D1 · R5(컨테이너 투과)를 이번 범위에 **포함**한다

- Status: `[번복됨]` — 인계 문서의 "R5 제외" 지시를 뒤집는다
- 확신도: 🔵 90 — 제외 근거였던 "문자열이라 파싱 필요" 가 실측으로 무너졌다
- 옵션 2 (포함 / 핸드오프대로 제외)
- 근거: `list[Foo]` 가 `ExprSubscript{left, slice}` 로 온다. 껍데기를 벗기는 코드가
  C# `resolve()` 와 같은 모양이라 비용이 작다. 안 하면 타입주석을 쓴 Python 코드에서
  관계가 통째로 사라진다

### D2 · 골든 테스트 대상 = 합성 픽스처 + 빈약한 자기호스팅

- Status: `[승인됨]` — 사용자 선택(2026-08-30)
- 확신도: 🔵 90 — `machine/` 의 클래스 1개는 실측이다
- 옵션 3 (합성 픽스처 / griffe 자기 패키지 / 외부 Python 저장소)
- 실제 불변식은 tmp_path 에 쓴 픽스처 패키지를 **진짜 griffe 로 덤프**해 검증하고,
  `machine/` 자기호스팅은 "파이프라인이 죽지 않는다" 연기 시험으로만 남긴다

### D3 · kind 사상은 association-only — 소유 kind 를 만들지 않는다

- Status: `[제안됨]`
- 확신도: 🔵 90 — C# 이 같은 이유로 이미 그렇게 한다(`normalize.py` 의 "C# 정상 — 함정 5")
- 옵션 0
- Python 은 모든 바인딩이 참조라 값 멤버/포인터 멤버 구분이 아예 없다.
  상속 = `inheritance` · 속성 주석 = `association` · 시그니처 = `dependency`

### D4 · 노드 입도는 클래스로 둔다 — 함수 노드는 이번 범위 밖

- Status: `[제안됨]`
- 확신도: 🟡 70 — 계약(C++/C# 노드 = 타입)과는 맞지만, Python 코드에서 정보 손실이 크다
- 옵션 2 (클래스만 / 클래스 + 모듈수준 함수)
- 대가: `machine/` 의 함수 265개가 전부 간선을 못 만든다. C++ 은 `clang-doc` 이 함수 노드를
  따로 만드는 선례가 있어 같은 길이 열려 있으나 이번엔 열지 않는다

### D5 · 모듈 경계는 기존 `module_of()` 를 재사용한다

- Status: `[제안됨]`
- 확신도: 🟡 78 — 결과는 같지만 그 함수의 주인은 C++ 이다
- 옵션 2 (재사용 / `py_module_of()` 신설)
- 폴더 트리 규칙이 Python 에도 그대로 맞고, src-layout(`src/pkg/...`)까지 이미 처리한다.
  C++ 사정으로 그 함수가 바뀔 때 시끄럽게 깨지도록 Python 전용 테스트를 함께 박는다

## 신규 구조물 신고

`normalize_python()` + 헬퍼 4개(`py_external_group` · `py_expr_name` · `py_resolve` ·
`py_walk_expr`) + 상수 3개. 새 파일 없음, 새 클래스 없음, 새 인터페이스 없음.

- 구현자 1 · 소비자 1 (`main()` 의 셋째 갈래)
- 삭제 시험: 이 다섯 함수를 지우면 Python 갈래만 사라지고 C++/C# 은 그대로 돈다
- 근거: 기존 `normalize_cpp` / `normalize_csharp` 가 같은 모양으로 이미 둘 있다.
  세 번째를 같은 자리에 같은 방식으로 더하는 것이다
