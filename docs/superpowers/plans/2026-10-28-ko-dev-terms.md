> 재개 진입점과 0단계 실측: [`docs/handoffs/RESUME-2026-10-28-official-term-grounding.md`](../../handoffs/RESUME-2026-10-28-official-term-grounding.md)
> 1판(2026-10-28)은 git 이력에 있다. 언제 무엇이 바뀌었는지는 15절

## 0. 한 줄

LLM 이 한국어 개발 문서를 쓰다가 고른 (영어 개념, 한국어 낱말) 쌍이 개발 도메인에서 실제로 쓰이는 표기인지 확인할 때 꺼내 보는 조회 자료다.
영어 용어 하나(선택적으로 쓰는 이의 한국어 후보)를 넣으면, **등록된 단어집 모듈**에서 나온 한국어 후보와 근거(모듈 · 항목 id 또는 `파일:줄` · 개수 · 스냅숏)를 내놓는다.
**고르지 않는다.** 근거가 없으면 `근거 없음` 을 그대로 낸다.

이 저장소에서 만들지만 Mode 1.5 에만 딸린 것이 아니다. 어느 컴퓨터에서나 쓰는 범용 스킬이 목표이고,
뒤에 report-builder 와 코드베이스 위키 도구 양쪽에 쓰일 예정이다(사용자 진술).

## 1. 정해진 것

날짜는 15절. 모두 사용자 답이다.

| 축 | 결정 |
|---|---|
| 범위 | **독립 스킬까지.** Mode 1.5 · 2 · 위키 연결은 시범 결과를 보고 따로 정한다 |
| 조회 방향 | **영어 → 한국어만** |
| 자리 | **이 저장소 최상위 폴더 `ko-dev-terms/`** — Mode 를 개발하듯 자기 `CLAUDE.md` · `README.md` · 시험을 갖추고 게이트에 올린다. 저장소의 다른 축(`runner` · `machine` · `viz` · `tools`)을 import 하지 않는다. `SKILL.md` 는 폴더 안, `.claude/skills/ko-dev-terms` 링크로 보인다 |
| 이름 | **`ko-dev-terms`** |
| 단어집의 꼴 | **단어집 하나 = 모듈.** 사용자가 직접 받은 파일을 등록하면 붙고, 등록을 지우면 떨어진다 — DLL 을 붙이고 떼듯이 |
| 모듈의 꼴 (축 A) | **데이터 모듈 + 내장 읽기.** 모듈은 매니페스트 한 장과 사용자가 받은 파일이다. 알려진 형식의 읽기는 스킬 안에 두고, 그 밖의 형식은 공통 정규형(TSV)으로 바꿔 넣는다. **등록한 파일의 코드를 실행하지 않는다** |
| 제공 방식 (축 B) | **전부 매니페스트만.** 기본 층(std)의 단어집도 데이터는 사용자가 받는다. 저장소에는 URL · 고정값(해시 · 커밋) · 받는 명령만 둔다 |
| 기본 층 std | **구조(아키텍처) · 설계 · 소프트웨어 공학 · 프로그래밍 언어(특히 OOP) · 테스트 & 품질.** C++ 의 `std` 와 같은 층이고 1차 목표다 |
| 소프트웨어 공학의 경계 (축 C) | **요구공학 · 프로젝트 관리는 std 에서 뺀다** — 선택 모듈로 붙일 수 있다 |
| 무게 | **범위 · 우선순위의 뜻.** std 영역을 잘 덮는 쪽에 둔다. 후보에 점수를 매기지 않는다(G5) |
| 프레임워크 종속 단어집 | **권하지 않는다.** 쿠버네티스 · Python 은 제외했다(용어집과 본문 말뭉치 모두로 읽었다) |
| 범위 목록 (어떤 영어 용어를 덮나) | **국제 표준 어휘 + 사용자 목록.** LLM 이 "설계 용어인가" 를 판단하지 않는다 |
| 캐시 | **출처에서 직접 받는다.** 클라우드는 환경 캐시(설정 스크립트 스냅숏) |
| MS 라이선스 (D1) | 조건부 수락. zip 안에서 별도 약관이 나오면 원문을 보이고 다시 묻는다 |
| LLM 후보 (D4) | 표시를 붙여서만 — `후보 출처 = LLM (추론)` |
| 판정 순서 (D5) | 스킬에 넣지 않는다 |
| 시작 시점 (축 D) | **계획서를 먼저 다듬고 승인을 받는다** — 이 판이 그 결과다 |

## 2. 모듈

### 2-1. 모듈이 무엇인가

| 부분 | 무엇 | git |
|---|---|---|
| 매니페스트 | 모듈 하나에 한 장. 이름 · 층(std / 선택) · 영역 표지 · 역할 · 형식 · 받는 곳과 받는 명령 · 라이선스(이름 · URL · 파생 행 게시 가능 여부) · 고정값 · 의미 표지를 어디서 읽는가 | std 모듈의 매니페스트는 추적. 사용자 모듈은 사용자 몫 |
| 데이터 파일 | 사용자가 받은 원본. 매니페스트의 고정값과 대조한다 | **밖** |
| 색인 | 등록할 때 원본에서 정규형 행으로 만든 것 | **밖** |
| 등록부 | 지금 붙어 있는 모듈의 목록 | **밖** |

**역할 셋** — 한 모듈은 하나를 맡는다.

| 역할 | 무엇을 주나 | 예 |
|---|---|---|
| 한국어 짝 | 영어 ↔ 한국어 쌍과 그 출처 자신의 정의 · 의미 표지 | MS TBX · MDN 용어집 · cjk-compsci-terms |
| 영어 범위 목록 | 어떤 영어 용어가 std 범위인가 | iSAQB · GoF/SOLID/GRASP 이름 목록 · SEVOCAB 손 조회 |
| 빈도 말뭉치 | 한국어 산문에서 센 개수와 `한글(영어)` 병기 | MDN 한국어 본문 |

**손 조회 기록도 모듈이다.** SEVOCAB · ktword · TTA 처럼 일괄로 받을 수 없는 출처는, 사람이 조회한 결과를 정규형 TSV(조회 날짜 · URL · 항목 id 를 더한 꼴)로 적어 모듈로 등록한다.

### 2-2. 등록과 제거

명령 이름은 제안이다.

| 명령 | 하는 일 |
|---|---|
| `add <매니페스트> <받은 파일>` | 고정값을 대조하고(다르면 멈춘다 — G2), 정규형 색인을 만들고, 등록부에 올린다 |
| `remove <모듈>` | 등록부에서 내리고 그 모듈의 색인을 지운다. 받은 원본은 사용자 것이라 지우지 않는다 |
| `list` | 붙은 모듈 — 층 · 역할 · 라이선스 · 고정값 · 색인 상태 |
| `verify` | 붙은 모듈 전부의 고정값을 다시 대조한다 |
| `fetch-commands <모듈>` | 매니페스트의 받는 명령을 **보여 주기만** 한다. 실행은 사용자가 한다(축 B) |

### 2-3. 정규형

모든 읽기는 같은 행을 낸다. 알 수 없는 형식의 사용자 단어집도 이 꼴의 TSV 로 바꿔 넣으면 붙는다.

| 열 | 뜻 |
|---|---|
| `en` | 영어 표제 |
| `ko` | 한국어 표기 (영어 범위 목록 모듈은 비어 있다) |
| `entry` | 출처 안의 항목 id 또는 `파일:줄` |
| `sense` | 출처 자신의 정의나 의미 표지 — 같은 낱말의 다른 뜻을 가르는 열 (예: MS 정의, MDN 하위 폴더, iSAQB 정의 첫 줄) |
| `extra` | 손 조회의 날짜 · URL 같은 덧붙임 |

모듈 이름과 고정값은 등록부가 행마다 붙인다.

### 2-4. 매니페스트의 꼴

TOML 을 제안한다 — 저장소의 설정값 관례(`config/*.toml`)와 같다. 파이썬 표준 라이브러리 `tomllib` 은 3.11 부터 있어 Windows PC 의 파이썬 판(9절 M5)을 본 뒤 정한다. 3.11 보다 낮으면 JSON 이다.

## 4. 한국어 후보를 어디서 얻나

| 기호 | 후보 출처 | 결정적인가 |
|---|---|---|
| (a) | 한국어 짝 모듈의 대상어 (MS TBX · MDN · cjk-compsci-terms …) | 예 |
| (b) | 빈도 말뭉치의 병기 패턴 `<한글 낱말>\s*\(\s*<영어>\s*\)` | 예 |
| (c) | 사용자가 준 후보 — 조회 입력의 한국어 후보도 여기 | 예 |
| (d) | LLM 이 낸 후보 — 행마다 `후보 출처 = LLM (추론)`, 개수는 실측, 0 이면 0 | 아니오 (표시) |

## 5. 세기 규칙 (빈도 말뭉치)

- **산문만 센다.** 빼는 것: 머리말, 코드 블록, 인라인 코드, MDN 매크로 `{{ … }}`, HTML 주석.
- **경계 규칙 v1** — 앞 글자가 한글이 아니고, 뒤가 조사이거나 한글이 아닐 때만 센다(`트리` ⊂ `트리거` · `엣지` ⊂ `엣지케이스` 를 막는다). 조사 목록은 리소스 파일에 둔다.
- **정밀도 표본 검사** — 시범 낱말마다 개수가 100 이상이면 무작위 100줄, 아니면 전부를 사람이 본다.
- MDN `files/ko` 의 `conflicting` · `orphaned` 는 빼는 것을 기본으로 한다.

## 6. 출력 (G3 · G4 · G5)

- 한 행 = 원어 · 한국어 후보 · 모듈 · 근거(항목 id / `파일:줄` · 개수) · `sense` · 스냅숏 · 후보 출처.
- 모듈마다 범위를 적는다. 항목이 없으면 `근거 없음` 과 함께 "이 모듈의 범위 밖일 수 있음" 을 적는다(G4).
- 줄 세우기는 층(std 먼저)과 역할 순서뿐이다 — 판정이 아니다. 맨 끝에 `판정 : 하지 않음` (G5).
- 라이선스가 고지를 요구하는 모듈의 행이 하나라도 있으면 그 고지문을 붙인다(MS: "Entry from Microsoft Learn's Globalization Essentials. © … Microsoft Corporation. All rights reserved.").
- 행은 파이썬이 자료로 만들고, 글 꼴은 리소스 템플릿이 그린다(루트 `CLAUDE.md` 의 "리소스와 코드를 가른다").

## 7. 데이터 자리와 클라우드

**원본 · 색인 · 등록부는 저장소 밖에 둔다** — git 에 들어갈 길을 처음부터 없앤다. MS 라이선스 2(i) 가 "publish … for others to copy" 를 막는다.

| 무엇 | 자리 |
|---|---|
| 받은 원본 · 색인 · 등록부 | 환경 변수 `KO_DEV_TERMS_DATA`. 없으면 OS 캐시 폴더 — Linux · Mac `~/.cache/ko-dev-terms`, Windows `%LOCALAPPDATA%\ko-dev-terms` |
| std 모듈 매니페스트 | `ko-dev-terms/modules/` (git) |

- 받는 명령은 GitHub 저장소라면 `git clone --filter=blob:none --no-checkout` + sparse checkout + 매니페스트의 커밋. **GitHub 아카이브 URL(`codeload.github.com`)은 쓰지 않는다** — 클라우드의 GitHub 프록시가 세션에 붙이지 않은 저장소의 아카이브를 공개 저장소라도 403 으로 막는다(클라우드 환경 문서의 GitHub proxy 절).
- **클라우드** — 사용자가 환경 설정에서 허용 도메인(예: `download.microsoft.com`)을 더하고, 설정 스크립트(`tools/cloud_env.sh` 가 원본)에 받는 명령과 `add` 를 넣는다. 설정 스크립트가 약 5분 안에 끝나면 파일 시스템이 스냅숏되어 약 7일 동안 새 세션이 그것으로 시작한다. 넘기면 받기만 SessionStart 훅의 배경 작업으로 옮긴다.
- **로컬** — 처음 한 번 받아 등록하고, 그 뒤 조회는 오프라인이다(G6).
