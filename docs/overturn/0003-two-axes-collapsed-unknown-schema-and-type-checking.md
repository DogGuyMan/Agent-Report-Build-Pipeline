# 0003 · "스키마를 모른다" 와 "형 검사를 끈다" 를 한 덩어리로 묶었다

| | |
|---|---|
| 날짜 | 2026-09-08 |
| 자리 | 러너 공통 단계 기계 설계, D10 → D11 |
| 뒤집은 이 | 사용자 (그 뒤 실측으로 확정) |
| 상태 | 확정 |

## 무엇을 주장했나

설계 문서에 이렇게 적었다.

> `Records` 를 못 박지 않는 이유는 레코드의 칸을 배치 세션이 채우므로 러너가 정하지 않기
> 때문이다. **바깥 프로그램이 꼴을 정하는 것은 못 박지 않는다**
> (`AgentResult` 도 같은 이유로 `dict[str, Any]` 다).

## 무엇으로 뒤집혔나

사용자가 `Any` 를 일절 쓰지 말라고 지시했다. 그래서 탐침을 짜서 재 봤더니 두 가지가 나왔다.

- **`pyright strict` 는 명시적 `Any` 를 못 잡는다.** `Any` 로 받은 값에 없는 열쇠와 없는
  메서드를 붙여도 오류 0건이다. `reportExplicitAny` · `reportAny` 를 설정에 넣어도 무시된다
  (basedpyright 전용 규칙)
- **`Any` 를 한 개도 안 쓰고 `pyright strict` 0 오류가 가능하다.** `dict[str, object]` 로 받고
  `isinstance` 로 좁히면 된다. 실제로 짜서 통과시켰다

즉 스키마를 몰라도 `Any` 를 쓸 이유는 없었다.

## 왜 틀렸나 — 판단의 어느 단계에서 갈렸나

한 문장 안에 **직교하는 축 둘**을 넣고 하나로 결론냈다.

| 축 | 질문 | `AgentResult` 의 답 |
|---|---|---|
| 스키마 | 이 값의 **모양을 아는가** | 모른다. 바깥 프로그램이 정한다 |
| 검사 | 형 검사기를 **켜 둘 것인가** | **켤 수 있다** |

둘은 독립이다. 모양을 몰라도 "무엇인지 확인하고 쓰라" 고 강제할 수 있다. 그것이 `object` 다.
`Any` 는 모양을 모른다는 뜻이 아니라 **아무것도 확인하지 않겠다는 뜻**이다.

`design-decision-discipline` §2.7 이 말하는 축 붕괴(axis collapse)의 한 사례다. 다만 §2.7 은
*제안*이 여러 축을 묶는 것을 경계하는데, 여기서는 **기각 사유**가 축을 묶었다.
"X 라서 Y 를 포기한다" 는 문장도 축 선언의 대상이다.

## 패턴 — 다음에 쓸 검사

**"A 라서 B 를 포기한다" 를 쓸 때마다 A 와 B 가 같은 축인지 본다.**

문장을 이 꼴로 다시 써 본다.

    A 가 참이면서 B 를 포기하지 않는 방법이 정말 없는가?

이번 경우 A = "모양을 모른다", B = "형 검사". 답은 `object` 였다. 30초면 나왔을 질문인데
문장을 한 번에 쓰느라 안 물었다.

**특히 위험한 꼴 — 포기의 근거가 "어쩔 수 없다" 계열일 때.**
*"바깥이 정하는 것이라"* · *"동적이라"* · *"우리가 소유하지 않아서"* 로 시작하는 문장은
대개 축이 붙어 있다. 그런 문장을 쓰면 포기하는 대상(B)을 따로 적어 놓고 그것만 다시 본다.

**부수 교훈 — 도구가 무엇을 잡는지 실제로 돌려 본다.** 나는 `pyright strict` 가 `Any` 를
잡아 줄 것이라 암묵적으로 가정했다. 탐침 20줄로 반증됐다. 게이트를 근거로 삼을 때는
그 게이트가 정말 그것을 잡는지 한 번 재 본다.
