# 결정 0010 — `xmldoc` 주석 주입을 쓰지 않는다

**상태** 폐지 · 2026-09-13 · 사용자 지시 — *"xmldoc 사용안하는것으로 문서 동기화"*

## 무엇이 바뀌나

| 전 (0007 까지) | 후 |
|---|---|
| `xmldoc.py check` 가 게이트 일곱 중 하나 | **게이트에서 뺀다.** 게이트는 여섯이다 |
| 새 함수를 쓰면 레코드 → `emit` → `inject` 로 주석 블록을 박는다 | **`emit` · `inject` 를 돌리지 않는다.** 레코드(`machine/terms-reading.json`)는 Mode 1 의 입력이라 계속 쓴다 |
| 코드를 옮기면 `inject` 가 마커 기준으로 `where` 를 다시 센다 | `where` 의 신선도는 **`terms_db.py` 의 L1/L2/L3** 만 본다. 밀린 줄은 재조사(Mode 1 증분)나 손으로 고친다 |
| CI `docs-gates` 에 xmldoc 단계 | 뺀다 |

## 무엇이 남나 — 잔재이지 규약이 아니다

- 소스의 `# <include file="machine/comments.xml" …/>` 블록 약 500곳과 `machine/comments.xml`. **새로 심지 않고 고치지도 않는다.**
  지우는 것은 별개의 코드 작업이다 — 한 번에 지우면 diff 가 커서 사용자가 시점을 정한다.
- `machine/xmldoc.py` 파일 자체. `terms_db.py` 가 `Term` · `Terms` 형을 여기서 import 하므로 **모듈은 남는다.**
  주석 주입 명령(`emit` · `inject` · `check`)만 쓰지 않는다. 형을 `terms_db.py` 나 `codegraph_types.py` 로 옮기면 파일도 지울 수 있다.
- `machine/test_xmldoc.py` — 모듈이 남는 동안 같이 남는다. 지울 때 함께 지운다.

## 왜

0007 의 비용표 그대로다 — 키가 갈리면 마커가 통째로 끊기고(737건), 고치면 `comments.xml` 4884줄이 바뀌며,
주석은 썩는다. 2026-09-08~11 러너 리팩터링 뒤 `check` 가 **문제 341건**으로 빨간 채 머물렀고, 그것을 초록으로
돌리는 유일한 길이 다시 `emit → inject` 였다. 유지 비용만 있고 소비자가 없다 — 소스 안의 "쓰는 것 · 쓰이는 곳"
줄을 읽는 사람도 도구도 없었다. 0007 의 "대체안" 은 정하지 않는다 — 대체할 것이 없다는 것이 답이다.
의존 그래프는 `terms-db.json` 과 `codegraph.json` 에 있고 위키가 그것을 읽는다.

## 되살릴 조건

소스 안에서 의존 줄을 읽는 **실제 소비자**가 생기고, 키 개명에도 마커가 끊기지 않는 구조가 먼저 있을 때.
