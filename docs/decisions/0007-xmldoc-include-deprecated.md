# 0007 · `# <include …/>` 주석 주입을 폐지 예정으로 표시한다

| | |
|---|---|
| 날짜 | 2026-09-08 |
| 상태 | **폐지 예정 (deprecated).** 지우지 않는다 |
| 지시 | 사용자 — *"지금 지우지는 않지만 추후 개발에 obsolete 되도록 마크업을 달리하라. CLAUDE.md 뿐만 아니라 C# 의 Attribute 처럼"* |

## 무엇을 폐지하나

`machine/xmldoc.py` 가 소스에 주입하는 주석 블록이다. 지금 저장소에 **레퍼런스 751건**이 있다.

    # <include file="machine/comments.xml" path="//term[@id='machine.xmldoc.Term']"/>
    # 용어 하나를 나타내는 타입이다.
    # 쓰는 것: … · 쓰이는 곳: …

**지금 지우지 않는다.** 돌아가고 있고, 지우는 것은 별개 작업이다.
**새 코드에 이 마크업을 새로 심지 않는다** — 그것이 "폐지 예정" 의 뜻이다.

## 왜 — 이미 드러난 비용

| 사실 | 근거 |
|---|---|
| 레코드 키가 갈리면 마커가 통째로 끊긴다 | 2026-09-07 에 키 675개가 개명되자 `xmldoc check` 가 0 → **737건**이 됐다 (`docs/handoffs/HANDOFF-2026-09-07-warmup-increment-unreachable.md`) |
| 지금도 미해결 잔여가 있다 | `xmldoc check` **문제 94건** — 새 심볼 85개가 마커를 못 받았다 |
| 고치면 큰 diff 가 난다 | `emit` → `inject` 를 돌리면 `comments.xml` 만 4884줄이 바뀐다 |
| 주석은 썩는다 | 루트 `CLAUDE.md` 의 "주장이 아니라 시험으로 적는다" 와 방향이 어긋난다 |

## 표시 방법 — 세 갈래

| 안 | 무엇 | 대가 |
|---|---|---|
| **A. 생성기에 한 번** (권고) | `machine/comments.xml` 뿌리에 `deprecated` 속성, `machine/xmldoc.py` 에 모듈 수준 표시, `xmldoc.py check` 가 배너 한 줄을 낸다 | 파일 3개만 바뀐다. **751곳을 다시 주입하지 않는다.** C# 으로 치면 클래스에 `[Obsolete]` 를 다는 것 |
| B. 주입 자리마다 | `<include … deprecated="2026-09-08"/>` 로 태그에 속성을 더한다 | 751곳 전부 다시 주입해야 한다. 지금 미해결 94건과 diff 가 얽힌다 |
| C. 문서에만 | `CLAUDE.md` 한 줄 | 사용자가 명시적으로 "CLAUDE.md 뿐만 아니라" 라고 했다 |

**A 를 권고한다.** C# 의 `[Obsolete]` 도 호출 자리마다 붙이는 것이 아니라 **선언 한 곳**에 붙이고
컴파일러가 호출 자리에서 경고를 낸다. `xmldoc.py check` 가 그 컴파일러 자리다.

## 아직 정하지 않은 것 — 무엇으로 대체하나

**후보만 적는다. 혼자 정하지 않는다.**

| 후보 | 무엇 |
|---|---|
| 파이썬 독스트링만 | 언어가 이미 가진 자리. 다만 `쓰는 것 · 쓰이는 곳` 그래프가 사라진다 |
| 곁딸린 파일 | 소스를 안 건드리고 `terms-db.json` 쪽에만 산다. 코드를 읽는 사람이 못 본다 |
| 데코레이터 | 런타임 객체에 붙는다. 모듈·형 별칭에는 못 붙인다 |

**대체안이 정해지기 전까지 A 만 적용한다.** 표시는 표시이고 이주는 이주다.

## 되살릴 조건

`쓰는 것 · 쓰이는 곳` 그래프를 소스 안에서 읽는 것이 실제로 값어치가 있다고 판명되고,
키 개명(인계 문서 결함 ④)이 구조로 해결되면 폐지를 철회할 수 있다.
