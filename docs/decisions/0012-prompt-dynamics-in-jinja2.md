# 결정 0012 — 프롬프트의 동적 부분은 프롬프트 파일 안에서 Jinja2 로 쓴다

**상태** 제안됨 · 2026-10-24 · 사용자 판단 (해부 페이지 · 라이브러리 조사 · 재질의 하나를 거쳤다)

**무엇을.** LLM 프롬프트에서 파이썬이 대신 조립하던 꼴 — 목록 반복 · 빈 값 대체 글 · 있을 때만 붙는 절 ·
쉼표 잇기 · 들여쓰기 — 을 프롬프트 파일 안의 Jinja2 문법(`{% for %}…{% else %}` · `{% if %}` · `join` · `indent`)으로 옮긴다.
Jinja2 는 `requirements.txt` 에 적는 **명시 의존**이다 — "프롬프트 동적 생성 = Jinja2" 가 의존 목록에서 보인다.

- 파일은 **마크다운 그대로**다. 단계당 한 파일과 `<!-- section: 이름 -->` 절(0011 · 루트 `CLAUDE.md`)은 유지하고, 절 안의 글만 Jinja2 로 렌더한다.
- **결함 문구 9개**(고치는 법 `FIX` 5 · 결함 설명 4)는 결함 표 `runner/mode1/faults.toml` 로 옮긴다. 재조사 절에서 LLM 이 읽고
  동시에 `.bad.why` 에 기록되는 데이터라 프롬프트 절이 아니라 데이터 자리에 둔다. 갈래 이름은 `FaultKind` 와 같아야 하고 시험이 고정한다.
- **범위는 프롬프트만**이다. 파일 템플릿 일곱(`viz/templates/` · `runner/wiki/templates/`)은 `tools/template.py` 에 그대로 둔다.

**같이 정한 규칙.**
- **템플릿은 꼴만, 데이터 결정은 단계.** 어느 항목을 싣는가 · 무엇이 미조사인가 · 어느 결함이 났는가는 단계(파이썬)가 정해 넘긴다.
  템플릿은 받은 것을 어떻게 놓는가만 정한다. Jinja2 는 표현식과 필터가 있어 계산이 템플릿으로 새어 들 수 있으므로 이 규칙으로 막는다.
- **엄격 검사.** 빠진 값은 `StrictUndefined` 로, 템플릿이 쓰지 않는 남는 값은 `jinja2.meta.find_undeclared_variables` 대조로 둘 다 오류다.
  오타 자리가 조용히 빈 글로 LLM 에 가지 않게 하려는 것이다(R1 의 `STRAY` 검사와 같은 목적).
- **공백.** `trim_blocks` · `lstrip_blocks` · `keep_trailing_newline` 를 켠다. 블록 태그 줄이 빈 줄을 남기지 않게 한다.
- **바이트 대조는 합격 기준이 아니다.** 옮기는 김에 꼴을 고친다(예: 마무리 줄 "보고:" 뒤에 붙던 조건부 절을 본문의 맞는 자리로).
  프롬프트의 결과는 어차피 확률적이므로, 바뀐 글은 옮기기 전후 렌더를 diff 로 보아 사람이 판단한다.

**뒤집거나 고치는 것.**
- R10 · R11 의 제약 "새 서식 · 파서 · 렌더러 기능 금지" 를 **프롬프트에 한해** 푼다.
- R11 후보(한 줄 절 6개)는 적용하지 않고 이 이행에 합친다. 커밋 `8d71d38` 의 바이트 고정 시험과 `edge_dump` 경계 입력은 옮기기 전 모습의 비교 자료로 쓴다 — 꼴을 고치는 곳에서는 기대값을 새 꼴로 바꾼다.
- 루트 `CLAUDE.md` 최우선 규약의 "자리표시는 `{{이름}}` 하나다" 를 고친다 — 프롬프트는 Jinja2, 파일 템플릿은 `{{이름}}`.

**고르지 않은 것.**
- 렌더러에 자체 반복 · 기본값 문법을 여는 안(기본값만 · 줄 반복 · 블록) — 이미 있는 엔진을 빌리는 쪽이 문법을 새로 지키는 것보다 싸다.
- 프롬프트 옆의 조합기 모듈(파이썬 클래스가 자리를 채움) — 글 꼴 지식이 코드에 남는다.
- YAML 프롬프트 파일 · Prompty/Dotprompt 꼴의 YAML 머리 — 사용자가 마크다운으로 되돌렸다.
- Mustache(논리 없는 문법) — `join` · `indent` 같은 필터가 없어 그 부분이 파이썬으로 돌아간다.
- 프롬프트 전용 라이브러리(banks · Prompty · Dotprompt · POML · priompt 계열 · Guidance) — 대부분 Jinja2 · Handlebars 를 감싸거나
  모델 호출 · 토큰 예산 · 생성 제약 같은 다른 목적을 싣는다. 우리가 쓰는 것은 그 밑의 엔진뿐이다.
- 파일 템플릿까지 Jinja2 — 사용자가 범위를 프롬프트로 좁혔다.

**대가로 받아들인 것.** 렌더러가 둘이 된다(프롬프트 Jinja2 · 파일 템플릿 `tools/template.py`). 의존이 하나 는다(jinja2 와 그 의존 MarkupSafe).
템플릿 안 논리가 자라는 것은 규칙으로만 막는다. 옮기기 전후가 같다는 기계 보장이 사라진다.

**새 구조 공개(설계 규율 §2.5 — 2026-10-24 실측).**
1. 구현자 — Jinja2 환경 하나(`PromptResource` 안) · 결함 표 읽기 하나.
2. 소비자 — 프롬프트를 선언한 단계 클래스 6(`prompt_names` 를 가진 파일 5) · 결함 문구를 쓰는 곳(`FIX` 표 · 결함 설명 4자리 · `check_shard.py`).
   옮겨 올 수요 — 반복 6 · 빈 값 대체 6 · 조건부 절 4 · 쉼표 잇기 2 · 맨 값 목록 1 · 들여쓰기 1 · 끝 줄바꿈 손질 16.
3. 삭제 시험 — Jinja2 를 빼면 위 수요가 파이썬 조립과 한 줄 절(지금 21개 중 데이터 문구를 뺀 12개)로 돌아온다.
4. 계획과의 관계 — rev.4 밖. 0011 의 "단계당 한 파일" 은 지키고, R10 · R11 제약은 프롬프트에 한해 푼다.

**되살릴 조건.**
- 템플릿 안 계산이 데이터 결정으로 번진 사례가 두 번 나오면 논리 없는 문법(Mustache)이나 조합기를 다시 본다.
- 파일 템플릿 쪽에 반복 · 조건 수요가 생기면 그쪽도 Jinja2 로 옮기는 것을 다시 본다.
